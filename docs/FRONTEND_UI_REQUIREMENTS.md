# 夜霜封面前端 UI 与动作视频需求

版本：1.0  
适用范围：夜霜 Windows 原生桌面程序封面、动作视频层和协作预览页

## 1. 产品目标

封面要让夜霜始终像“同一个角色、同一个镜头、同一个空间”中自然存在。语音、动作和 UI 状态可以变化，但人物位置、光线、画面比例和视觉重心不能漂移。

界面保留夜蓝、星光、银蓝长发人物和非对称构图。人物是第一视觉焦点；UI 信息用于表达“正在听、思考中、正在说话”，不能用大面积卡片或黑色遮罩压住人物。

## 2. 不可改变的视觉基准

- 唯一基准图：`assets/scene-pack/base/yeshuang-base.png`。
- 基准画布：`1536 × 1024`，比例为 `3:2`。
- 人物、手、桌沿、饰品和头发的位置以基准图为准。
- 场景层使用 `object-fit: contain` 和 `object-position: right center`。
- 不做持续放大、镜头推进、视差缩放或为了“动感”改变人物比例。
- 不在顶部、左侧或人物附近叠加黑框遮挡水印。水印、字幕和黑边必须在素材制作阶段移除。
- 基准图始终位于视频层下方，动作视频只做透明度衔接。

## 3. 页面信息架构

### 3.1 左侧品牌区

- 左上保留当前书法感“夜霜 / Ye Shuang”品牌字样，不改成通用粗体标题。
- 品牌区包含角色短句、七个主导航入口和少量状态信息。
- 宽屏显示完整品牌和导航；中等宽度压缩文字；窄屏改为底部紧凑导航。
- 左侧区域可以有半透明深色底，但不得形成覆盖人物的实心黑墙。

### 3.2 中央人物与语音圆

- 人物保持右侧主视觉，不能因功能页切换而改变裁切或缩放。
- 语音圆表达真实状态：
  - `idle`：待机，可跟随背景音乐做非常轻的律动。
  - `listening`：显示“正在听”，按麦克风真实音量轻微律动。
  - `thinking`：显示“思考中”，呼吸式低频律动。
  - `speaking`：显示“正在说话”，按夜霜输出音量律动。
- 律动只改变光晕、描边或微小的整体比例，建议最大缩放不超过 `1.035`。
- 录音圆不能遮挡夜霜的脸、眼睛、嘴或手。

### 3.3 右侧状态栏

- 显示序号、当前状态、模型、时间和地点等低频信息。
- ≥1280px 时常驻；960–1279px 收入抽屉；820–959px 不占固定侧栏宽度。
- 状态文字对比度需要可读，但视觉权重低于人物和语音状态。

### 3.4 顶部控制

- 保留背景音乐、刷新、全屏、静谧模式和关闭。
- 关闭按钮必须真正退出程序并停止语音、视频和背景音乐。
- 全屏为桌面程序默认形态；退出全屏后仍需保持最小 `820×600` 可用。

## 4. 响应式与 Windows 缩放

支持 Windows 100%–200% 缩放和以下逻辑尺寸：

| 尺寸 | 要求 |
|---|---|
| ≥1280px | 完整左侧导航、中央人物与右侧状态栏 |
| 960–1279px | 紧凑左侧导航，右侧状态进入抽屉 |
| 820–959px | 单列内容、紧凑底部导航 |
| 高度 <720px | 隐藏装饰性长文案，缩小语音圆，输入区始终可见 |

必须测试：

- `820×600`
- `1040×680`
- `1460×900`
- `2560×1440`

所有尺寸均不得出现横向滚动条、被遮住的输入区、无法点击的按钮或跑出画面的语音圆。

## 5. 语音圆与画面的对齐算法

语音圆锚点保存在 `manifest.json`：

```json
{
  "voice_anchor": {
    "x": 0.19531,
    "y": 0.45508
  }
}
```

这里的 `x`、`y` 是相对于“实际显示出来的 3:2 场景内容”的归一化坐标，不是相对于浏览器窗口的坐标。

前端必须按以下步骤计算：

1. 读取场景容器宽高和基准图宽高。
2. 按 `contain` 计算实际显示宽高。
3. 按 `right center` 计算场景内容左上角偏移。
4. 使用 `left + displayedWidth × x`、`top + displayedHeight × y` 得到锚点。
5. 在小窗口内只允许对语音圆做边界限制，不能移动或缩放人物来追圆。
6. 窗口缩放、DPI 改变、全屏切换和视频元数据加载完成后都要重新计算。

## 6. 动作视频技术规范

### 6.1 必须满足

- 成片分辨率：`1536×1024`。
- 帧率：优先 24 FPS，可接受 30 FPS；同一动作内恒定帧率。
- 编码：H.264，像素格式 `yuv420p`，MP4 容器，开启 fast start。
- 音频：无。所有声音由语音和背景音乐系统独立播放。
- 镜头：固定，不平移、不推拉、不缩放、不改变焦段。
- 首帧和尾帧：都要能与统一基准图自然叠合。
- 人物一致：脸型、五官、发饰、耳饰、手指、衣服、桌沿和光线不能突变。
- 清洁画面：无水印、字幕、Logo、黑边、黑框、平台 UI 或提示词残留。
- 动作幅度：克制、自然、符合夜霜清冷灵动的人设。

### 6.2 禁止出现

- 中间闪出 Q 版、不同脸、额外手指、饰品跳位或另一套服装。
- 慢动作眨眼、长时间闭眼、嘴型冻结后突然跳变。
- 视频整体逐渐放大或缩小。
- 黑帧、白闪、色温突变、曝光抽动。
- 为了首尾一致而机械倒放明显的人体动作。
- 动作视频自带声音，导致与 CosyVoice 或背景音乐叠音。

### 6.3 动作时长建议

| 动作 | 建议时长 | 备注 |
|---|---:|---|
| 普通眨眼 | 2–5s 成片 | 真正闭合到睁开约 0.18–0.35s，其余为自然待机 |
| 慵懒合眼/浅睡 | 5–10s | 可以缓慢闭眼、停留和恢复；保留原始慢节奏，动作名使用 `drowsy` 或 `sleepy` |
| 呼吸/发丝微动 | 3–8s | 首尾接近基准，幅度很小 |
| 倾听/侧头 | 2–5s | 进入和退出都回到基准 |
| 思考/移开目光 | 2–5s | 避免长时间闭眼 |
| 说话 | 2–6s | 口型自然，首尾为闭嘴或中性口型 |
| 情绪动作 | 1.5–5s | 每条只表达一个清楚情绪 |

## 7. 状态与动作分类

动作按目录和 `manifest.json` 的 `state` 分类：

```text
clips/
  idle/
  listening/
  thinking/
  speaking/
  emotion/
```

推荐优先级：

```text
speaking > listening > thinking > emotion > idle
```

- `idle`：系统空闲时随机播放一次，结束后回到基准图。
- `listening`：录音开始立即切入；录音结束立即让位给 `thinking`。
- `thinking`：等待模型回复时使用；开始朗读后让位给 `speaking`。
- `speaking`：与语音播放同步开始；语音停止、打断或报错时立即结束。
- `emotion`：由回复语义触发，不得抢占录音和正在说话状态。

当前包含一段普通 `idle` 眨眼和一段慵懒 `idle` 合眼。没有对应动作的状态必须安全回到基准图，不能误播待机视频冒充口型。

## 8. 播放与衔接

- 基准图一直可见，动作层使用绝对定位完整覆盖同一场景矩形。
- 动作视频不得改变 `transform`、宽高、`object-fit` 或 `object-position`。
- 普通动作淡入淡出时间默认 `420ms`。
- 语音状态切换默认 `220ms`，保证响应快。
- 待机动作之间随机等待 `2600–5200ms`。
- 同一状态有多个动作时按 `weight` 加权随机，至少两个可用动作时避免连续重复。
- 任意时刻最多一个动作视频处于可见和播放状态。
- 切换前先准备下一段；加载失败时保持基准图，不出现空白或黑闪。
- 不硬切。轻微重影可以接受，但双层视频不能长期同时播放。
- 用户打断、静音、窗口隐藏、关闭程序时必须停止相应播放和计时器。

## 9. `manifest.json` 字段

每段视频至少登记：

```json
{
  "id": "speaking-soft-01",
  "state": "speaking",
  "action": "soft-talk",
  "src": "assets/scene-pack/clips/speaking/speaking-soft-01.mp4",
  "enabled": true,
  "playback": "once",
  "weight": 1,
  "duration_seconds": 3.8,
  "fps": 24,
  "width": 1536,
  "height": 1024,
  "action_window_seconds": [0.4, 3.3],
  "sha256": "..."
}
```

规则：

- `id` 使用小写英文、数字和短横线，且全局唯一。
- `state` 只能是 `idle`、`listening`、`thinking`、`speaking`、`emotion`。
- `action` 描述动作本身，不写文件日期或生成平台。
- `enabled: false` 可临时下线问题素材，不要直接删除历史记录。
- `action_window_seconds` 标出真实动作发生区间，方便后续做更精确的语音同步。
- `sha256` 由工具生成，用于发现素材被误替换。

## 10. 前端动效与音量反馈

- 星光粒子保持低密度、慢速，不能像游戏技能特效一样抢眼。
- 背景音乐只驱动非常轻的待机律动。
- 麦克风输入驱动 `listening` 律动；语音输出驱动 `speaking` 律动。
- 音量信号需要平滑和限幅，避免圆环抖动。
- 开启“减少动态效果”时，停止星点位移和尺寸律动，但状态文字仍要更新。
- 背景音乐在夜霜说话时降低音量，语音结束后平滑恢复。

## 11. 功能页要求

七个已有页面均需保留，不能因为增加动作而破坏：

1. 主页：问候、语音模式、停止朗读、运行状态。
2. 对话：文字、按住说话、点击开始/结束、连续对话、打断和历史。
3. 日记：日期校验、读取、生成、失败重试。
4. 生活流：安全只读、刷新和空态。
5. 记忆：安全只读、刷新和空态。
6. 运行时：启动、停止、重启和模型探针。
7. 设置：模型、声线风格、交互模式、主动策略、音乐导入和校验。

每页必须有加载、空数据、错误、重试、禁用、成功反馈和清楚的键盘焦点状态。任何按钮都不能点击后没有反应。

## 12. 验收标准

每个 Pull Request 合并前至少确认：

- 四种目标尺寸无横向溢出，导航、输入区和状态信息可用。
- 基准图、动作层尺寸和位置逐像素一致，没有缩放跳动。
- 语音圆在窗口缩放和全屏切换后仍对准。
- 动作首尾无硬切、黑闪、Q 版闪帧或明显变脸。
- 普通眨眼保持正常时长；慵懒合眼保持原始慢节奏，两者不能混用动作分类。
- 动作随机播放不会连续重复同一条。
- `listening`、`thinking`、`speaking` 状态切换及时，语音停止后回到待机。
- 背景音乐压低、语音打断、窗口关闭和单实例唤回均不回归。
- `python tools/yeshuang_scene_pack.py validate` 通过。

## 13. 同事交付一段动作时需要提供

- 最终 MP4。
- 动作状态与动作名。
- 动作真实发生的起止时间。
- 是否允许循环；默认按单次播放处理。
- 原素材来源和使用授权说明。
- 四种尺寸预览截图或录屏。
- 已知瑕疵；有瑕疵时先设为 `enabled: false`。
